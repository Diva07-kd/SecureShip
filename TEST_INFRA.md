# SecureScan Testing Infrastructure Specification (`TEST_INFRA.md`)

## 1. Executive Summary

SecureScan is an enterprise-grade security analysis web platform wrapping the SecureShip multi-engine SAST/SCA/Secret/IaC CLI within a high-performance Python FastAPI service and a modern dark-themed React dashboard. 

The test infrastructure establishes a multi-tiered, opaque-box and contract-driven verification suite spanning Tiers 1 through 4. It guarantees that security invariants (Zip-Slip traversal, symlink interception, decompression bombs, memory quotas), queue concurrency limits, subprocess execution safety, report taxonomy enrichment (CWE / OWASP Top 10), and multi-format exporters (JSON, OASIS SARIF 2.1.0, standalone HTML, binary PDF) are validated under adversarial conditions before deployment.

## 4. Multi-Tier Testing Strategy

The E2E test suite is organized into 4 distinct validation tiers:

### 4.1 Tier 1: Core Feature Coverage (`test_tier1_feature_coverage.py`)
Verifies that all primary interfaces and contracts function correctly under standard operating conditions:
1. **Safe Extraction Happy Path**: Extracts valid archives into isolated scratch directories, maintaining file permissions and relative structures.
2. **Upload Endpoint (`POST /api/scan`)**: Accepts multipart form zip upload $\le 50\text{ MB}$, returns HTTP 200 with valid UUID4 `job_id`, `status: "queued"`, and `poll_url: "/api/jobs/{id}"`.
3. **Job Polling Endpoint (`GET /api/jobs/{id}`)**: Returns real-time status (`queued`, `running`, `done`, `failed`) and integer progress percentage.
4. **Report Retrieval Endpoint (`GET /api/reports/{id}`)**: Returns unified `ScanReport` JSON object conforming to findings schema.
5. **Multi-Format Exporters (`GET /api/reports/{id}/export`)**: Validates query parameter routing for `format=json`, `format=sarif`, `format=html`, and `format=pdf`.
6. **Health Endpoint (`GET /api/health`)**: Returns service status `healthy`, active queue depth, and scanner subsystem readiness.
7. **Subprocess Invocation Contract**: Confirms execution uses argument list form (`["secureship", "scan", ...]` or `["node", "dist/index.js", "scan", ...]`) without shell interpolation.

### 4.2 Tier 2: Boundary & Corner Cases (`test_tier2_boundaries.py`)
Validates defensive barriers, size quotas, and fault injection handling:
1. **Zip-Slip Defense**: Rejection of absolute paths, drive letters, and traversal components (`..`).
2. **Symlink Defense**: Rejection of POSIX symbolic links identified by external attributes `0xA1ED` or `(mode & 0o170000) == 0o120000`.
3. **Zip-Bomb Defense**: Immediate rejection of decompression ratios exceeding 100x.
4. **Single-File Quota**: Strict rejection of individual uncompressed files exceeding $10\text{ MB}$ ($10,485,760\text{ bytes}$).
5. **Total-Archive Quota**: Strict rejection of total uncompressed archive volume exceeding $50\text{ MB}$ ($52,428,800\text{ bytes}$).
6. **Corrupt / Malformed Payload Handling**: Safe handling of truncated magic bytes, missing central directories, or zero-byte payloads.
7. **CLI Exit Code Semantics**: Verification that both exit code `0` (clean) and exit code `1` (findings detected) are treated as successful scans, while exit codes $\ge 2$ trigger `FAILED` status.
8. **Hard Timeout Enforcement**: Verification that execution exceeding 300 seconds triggers process termination and marks the job as `failed` with a timeout error.

### 4.3 Tier 3: Cross-Feature Interactions & Concurrency (`test_tier3_cross_features.py`)
Verifies queue scheduling, race conditions, lifecycle transitions, and memory cleanup:
1. **Queue Concurrency Floor**: Strict enforcement of `asyncio.Queue` concurrency $= 1$. When 3 scans are uploaded simultaneously, exactly 1 executes while 2 remain queued.
2. **State Machine Lifecycle**: Deterministic state transitions from `queued` $\rightarrow$ `running` $\rightarrow$ `done` (or `failed`).
3. **Premature Export Protection**: Requests for report export while a job is `queued` or `running` return HTTP 409 (Conflict) or HTTP 404 (Not Found).
4. **Context Manager Workspace Cleanup**: Ensures temporary extraction directories (`/tmp/securescan_*`) are purged upon job completion and upon job failure.

### 4.4 Tier 4: Real-World Scenarios & Output Fidelity (`test_tier4_real_world.py`)
Verifies end-to-end user workflows against realistic codebases:
1. **Clean Codebase Verification**: Complete end-to-end scan of `valid_clean.zip`, verifying exit code 0, 0 findings, and complete report generation.
2. **Vulnerable Codebase Verification**: Complete end-to-end scan of `valid_vulnerable.zip`, verifying detection of hardcoded AWS keys, SQL injection, command injection, and deserialization.
3. **Taxonomy & Snippet Verification**:
   - Verification that CWE IDs are extracted and populated.
   - Verification that findings are mapped to OWASP Top 10 (2021) categories (`A02:2021-Cryptographic Failures`, `A03:2021-Injection`, `A08:2021-Software and Data Integrity Failures`).
   - Verification that code snippet extractor slices $\pm 5$ lines around reported line with `is_vulnerable` flag correctly set.
4. **Exporter Output Verification**:
   - JSON export matches unified report schema.
   - SARIF export validates against OASIS SARIF 2.1.0 specifications (`version: "2.1.0"`, `runs`, `tool.driver`, `results`).
   - HTML export produces standalone single-file HTML with embedded inline CSS and no external CDN dependencies.
   - PDF export produces valid binary PDF beginning with `%PDF-` magic header and structured ReportLab elements.

## 5. Test Execution & Verification Guide

### 5.1 Prerequisites & Python Environment
- Python 3.11+ (Python 3.12.10 verified in workspace).
- Required packages: `pytest`, `pytest-asyncio`, `httpx`, `fastapi`, `pydantic`, `reportlab`.

### 5.2 Fixture Generation & Validation
To deterministically regenerate and audit all test archives:
```powershell
python tests/fixtures/generate_fixtures.py
```

### 5.3 Running the Full E2E Test Suite
To execute the complete E2E test suite across all 4 tiers:
```powershell
pytest tests/e2e -v
```

To run a specific tier:
```powershell
# Tier 1: Core Feature Coverage
pytest tests/e2e/test_tier1_feature_coverage.py -v

# Tier 2: Boundaries & Invariants
pytest tests/e2e/test_tier2_boundaries.py -v

# Tier 3: Concurrency & Queue Interactions
pytest tests/e2e/test_tier3_cross_features.py -v

# Tier 4: Real-World Scenarios & Taxonomies
pytest tests/e2e/test_tier4_real_world.py -v
```

### 5.4 Environment Flags
The test harness supports environment variable overrides:
- `SECURESCAN_API_URL`: Set to test against an external live HTTP server (e.g. `http://localhost:8000`). If omitted, tests utilize in-process client and direct component verification.
- `SECURESHIP_CLI_PATH`: Explicit path to SecureShip CLI entrypoint (defaults to `packages/cli/dist/index.js` or `secureship` binary).
